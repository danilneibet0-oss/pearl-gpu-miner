# Pearl (PRL) — учебный GPU-майнер pearlhash / NoisyGEMM

Учебная реализация поиска джекпота Pearl на INT8 тензорных ядрах (RTX 3060 Ti, Ampere, sm_86, Windows).
Источник истины — CPU-эталон `pearlhash_ref.py`; всё на GPU сверяется с ним **побитово**.
Официальный код: <https://github.com/pearl-research-labs/pearl> (клонируется в `pearl/`, используется только он).

## Что здесь есть

| Файл | Назначение |

| `pearl_gpu.py` | ядра джекпота: `jackpot_v2` (shared memory + cp.async + mma.sync m16n8k32 s8) и простое универсальное |
| `pearl_pipeline.py` | остальное на GPU: случайные A/B, BLAKE3 матриц, сиды, шум, BLAKE3 джекпотов, поиск по сложности |

| `run_miner.py` | цикл майнинга для локального gateway: задание → GPU → PlainProof → проверка → отправка |
| `stratum_client.py`, `run_stratum.py` | клиент и цикл для пула по Stratum (диалект из публичной спецификации Suprnova) |
| `miner.py`, `start_miner.bat`, `start_pool.bat` | командная строка в стиле Miner.exe и батники запуска (`start_pool.bat` — ваш личный, в git не попадает) |
| `build_exe.py`, `selftest.py`, `gpu_arch.py`, `dist_files/` | сборка Miner.exe, самопроверка, определение архитектуры GPU, шаблоны для раздачи |
| `bench_gpu.py` | бенчмарк ядра и стадий конвейера |
| `test_pearlhash_*.py`, `test_gateway_client.py` | 178 тестов (бит-в-бит против эталона, официальный верификатор, фейковый gateway) |

## Установка

Нужно: Windows, видеокарта NVIDIA с драйвером, поддерживающим CUDA 13 (проверено: драйвер 617.42, CUDA 13.4),
Visual Studio 2022 (Build Tools, компонент «Разработка классических приложений на C++») — он нужен Rust для линковки.
**CUDA Toolkit целиком ставить не нужно**: NVRTC и рантайм приходят из pip-пакета CuPy.

1. Python 3.12 или 3.13 (py-pearl-mining требует ≥ 3.12; 3.14 для этого проекта не использовался):

   ```powershell
   py install 3.13
   py -3.13 -m venv .venv
   .\.venv\Scripts\python -m pip install -U pip
   ```

2. Пакеты:

   ```powershell
   .\.venv\Scripts\python -m pip install numpy blake3 pytest maturin fastjsonschema "cupy-cuda13x[ctk]"
   ```

3. Официальный репозиторий (только он):

   ```powershell
   git clone --depth 1 https://github.com/pearl-research-labs/pearl
   ```

4. Rust (<https://rustup.rs>, профиль minimal, toolchain stable) и сборка биндингов. Первая сборка тянет plonky2 и
   занимает несколько минут:

   ```powershell
   $env:PATH = "$env:USERPROFILE\.cargo\bin;$PWD\.venv\Scripts;$env:PATH"
   $env:VIRTUAL_ENV = "$PWD\.venv"
   cd pearl\py-pearl-mining
   maturin develop --release
   cd ..\..
   ```

   После этого `import pearl_mining` работает внутри `.venv`.

### Важно знать при установке

* **Кириллица/пробелы в пути venv.** Встроенные «элементные» ядра CuPy (`cp.full`, `.fill`, арифметика над массивами и т. п.)
  не компилируются, если в пути к venv есть кириллица (ошибка `cannot open source file "cupy/complex.cuh"`).
  Код проекта намеренно использует только свои ядра, поэтому работает и в `D:\мои проги\майнер`, но при расширении
  кода либо избегайте таких вызовов, либо создайте venv в ASCII-пути.
* **Архитектура зашита:** ядра компилируются с `-arch=sm_86` (RTX 30xx). Для другой карты поменяйте `-arch` в
  `pearl_gpu.py` и `pearl_pipeline.py` (и перепроверьте размер shared memory в `jackpot_v2`).
* Запускайте `pytest` с перечислением файлов (ниже): голый `pytest` в этой папке подхватит тесты из клона `pearl/`
  (им нужен `torch`).

## Тесты

```powershell
.\.venv\Scripts\python -m pytest -q test_pearlhash_ref.py test_pearlhash_gpu.py test_pearlhash_pipeline.py test_pearlhash_proof.py test_gateway_client.py test_stratum_client.py
```

Ожидается `209 passed` (с `test_stratum_client.py`). Что проверяется:

* **GPU = эталон побитово:** ядро джекпота на пяти паттернах тайлов, k = 1024…5120 (в том числе k > 16·rank, когда слоты
  джекпота переиспользуются, и k с «хвостом» меньше rank), rank 64/128/256, крайние значения int8 (−128…127).
* **BLAKE3 матриц** (keyed, добивка нулями до 1024) на 1…66000 чанках, сиды и шум — для cert_version 1, 2 и 3.
* **Весь цикл попытки** при тех же A, B и заголовке даёт те же строки, столбцы и хеш, что `pearlhash_ref.try_mine_one`
  (cert 2 и 3; лёгкая, средняя и недостижимая сложность — тест не вырожденный).
* **Официальный Rust-верификатор** (`verify_plain_proof_for_cert_version`) принимает наши PlainProof; отклоняет решение
  не той версии сертификата, более жёсткую сложность и подделанную матрицу.
* **Клиент gateway** на локальном фейковом сервере (127.0.0.1, без внешней сети; сервер использует официальные
  JSON-схемы и официальный верификатор).

## Бенчмарк

```powershell
$env:PYTHONPATH = "."; .\.venv\Scripts\python bench_gpu.py            # ядро + стадии GPU-конвейера
$env:PYTHONPATH = "."; .\.venv\Scripts\python bench_gpu.py --kernel   # только ядро
```

Результаты на RTX 3060 Ti (38 SM), k ≥ 2048 (требование протокола), rank 128, тайл 4×16. Показан диапазон по разным
запускам: **GPU делится с рабочим столом (WDDM)**, и фоновая нагрузка (анимированные обои, оверлеи и т. п.) заметно
меняет цифры — одно и то же ядро давало 35.5 TMAC/s на «тихой» системе и ≈ 25–28 TMAC/s при фоновой загрузке GPU
(простое ядро в те же моменты — 5.4 и 3.6 TMAC/s). Для честных замеров закройте всё, что рисует на GPU; бенчмарк
берёт лучшее из нескольких серий.

| m × n × k | ядро, TMAC/s | TOPS (2 оп/MAC) | % плотного INT8-пика |
|---|---|---|---|
| 2048×2048×2048 | 25–33 | 50–66 | 39–51% |
| 4096×4096×2048 | 25–36 | 50–71 | 39–55% |
| 4096×4096×4096 | 24–37 | 49–74 | 37–57% |

Весь цикл попытки 4096×4096×2048, три попытки одновременно в разных CUDA-потоках (так работает `run_miner.py`):
≈ 1.9 мс на попытку, ≈ 520 попыток/с, ≈ 18 TMAC/s эффективно (≈ 36 TOPS) при той же фоновой нагрузке.
Что сделано для скорости: хеши матриц, сиды, шум, ядро джекпота и поиск по сложности связаны через память GPU без
синхронизации с хостом; хеш каждого тайла и сравнение со сложностью выполняются **внутри** ядра джекпота (массив
джекпотов в память не пишется; он пересчитывается только при находке); BLAKE3-дерево сливается ядрами по 1024 узла;
шум обеих матриц — два запуска; генерация A/B пишет по 16 байт. Пик 129.6 TOPS — оценка по паспортным данным 3060 Ti,
а не измерение. Потребление и температура не измерялись.

### Про единицы «TH/s»

Что именно рынок называет «хешем» в «64–65 TH/s», **в официальном репозитории не определено** (слов TH/s там нет).
Единственное близкое определение — `inner_hash_per_matmul` в `miner/miner-base/src/miner_base/noisy_gemm.py`: число
int8-умножений-сложений (MAC) внутри хеш-тайлов, то есть `высота_тайла × ширина_тайла × k` на тайл. Из этого следуют
две трактовки (это **гипотеза**, не установленный факт):

| Трактовка | Наше ядро | Весь конвейер |
|---|---|---|
| 1 «хеш» = 1 MAC (TMAC/s) | ≈ 25–36 | ≈ 18 |
| 1 «хеш» = 2 операции (TOPS) | ≈ 50–71 | ≈ 36 |

Для 3060 Ti плотный INT8-пик ≈ 130 TOPS (≈ 65 TMAC/s). Показатель 64–65 при ~100 Вт как 1 MAC означал бы почти 100% пика —
нереалистично, поэтому вероятнее вторая трактовка (≈ 50% пика). Если она верна, ядро по чистой скорости близко к уровню
готовых майнеров (на «тихой» системе), а весь наш конвейер — примерно вдвое медленнее: остальные стадии пока занимают
около половины времени попытки.

## Запуск майнинга

Нужен запущенный **официальный** pearl-gateway (он слушает только `127.0.0.1:8337`; см. `pearl/miner/pearl-gateway`) с узлом Pearl.

```powershell
.\.venv\Scripts\python run_miner.py --port 8337 --m 4096 --n 4096 --k 2048
```

Цикл: `getMiningInfo` (заголовок, цель, **cert_version из задания**) → попытки на GPU → при находке строится
`PlainProof` → проверка `verify_plain_proof_for_cert_version` → `submitPlainProof`. Решения, не прошедшие локальную
проверку, не отправляются. Граница сложности считается как у gateway: `target × размер_тайла × (k/rank) × 128`.

Ограничения параметров (правила протокола): `rank` — степень двойки ≥ 128, `k ≥ 16·rank`, `k % 64 == 0`, `k ≤ 4·rank²`,
`m` и `n` кратны периодам паттернов (для дефолтного паттерна 128). Для быстрого ядра `m`, `n` должны быть кратны 128.

## Майнинг в пул (Stratum)

```powershell
.\.venv\Scripts\python miner.py --disable-cpu --algorithm pearlhash --stratum --pool prl-ru.kryptex.network:7048 --wallet <ВАШ_USERNAME>/worker1
```

или отредактируйте `POOL`/`WALLET` в `start_pool.bat` и запустите его (он спросит подтверждение перед подключением).
Без флага `--stratum` майнер к внешним серверам не подключается.

**Протокол Kryptex «v2» (gzip).** По описанию Kryptex (<https://gist.github.com/maxmalysh/eaaf4332dbc5ca99d0a78f24a733fffe>)
в `mining.authorize` передаётся `"type":"v2"`; если пул подтвердил его в ответе, `plain_proof` отправляется сжатым gzip
(у нас: `base64(gzip(байты PlainProof))`; порядок base64/gzip в гисте не описан — это самое вероятное прочтение,
проверено только на фейковом пуле и ранее принятым raw-шаром). Имя воркера передаётся склейкой `wallet.worker`
(Kryptex берёт его оттуда; явное поле `worker` не используется пулом).

**Разреженные матрицы.** Случайные A и B почти не сжимаются (gzip ≈ 1.1×), поэтому при подтверждённом gzip майнер по
умолчанию берёт A и B почти нулевыми (по 32 случайные ячейки в каждой): доказательство сжимается ≈ 20×, шум, хеши и
сложность работают как раньше (проверено тестом: доля попыток с находкой та же, что у плотных матриц; официальный
верификатор принимает такие доказательства). Цена: само «полезное» умножение при этом фиктивное — майнер ищет
подходящие хеши, а не считает осмысленные матрицы. Флаг `--dense` возвращает случайные матрицы.

Режим длительной работы (`run_stratum.mine_forever`): при обрыве или таймауте майнер сам переподключается с паузой
2, 4, 8 … до 60 с (пауза сбрасывается после успешной авторизации); неверный кошелёк (коды 24/25) и серия из 3 отказов
шара подряд останавливают его без повторов; каждые 30 с печатается скорость (попыток/с, ≈ TMAC/s) и счётчики шаров
(принято / отклонено / устарело / дубликаты). Ctrl+C — остановка. Проверено на реальном пуле Kryptex: принятый шар за
≈ 150 с (≈ 110 тыс. попыток) — это одно наблюдение, а не оценка средней скорости.

Диалект реализован по публичной спецификации Suprnova (<https://prl.suprnova.cc/stratum-spec.html>): JSON по строкам,
`params` — объект, **без `mining.subscribe`**, `mining.authorize {wallet, worker, pass, agent}`, push `mining.notify
{header, height, job_id, target}`, `mining.submit {job_id, plain_proof}`, коды ошибок 20–27. Проверено на локальном
фейковом сервере по этой спецификации (с официальным верификатором доказательств), **но не на реальном пуле**.

Что неизвестно и сделано явными параметрами, а не догадками:

* **Подходит ли диалект Kryptex.** Спецификация утверждает, что он общий для экосистемы Pearl, но независимых
  подтверждений нет. Обычный `mining.subscribe` Kryptex на порту 7048 молча проигнорировал — это согласуется с
  диалектом без subscribe, но не доказывает его. Формат логина Kryptex (`username/worker`) в спецификации не описан.
* **`cert_version`** в `mining.notify` нет; по умолчанию 3 (`--cert-version`). От него зависят сиды шума: при неверном
  значении пул отклонит шары как невалидные.
* **Трактовка `target`:** как цель до штрафа ранга (как в задании gateway); граница джекпот-хеша =
  `target × размер_тайла × (k/rank) × 128`. Если пул считает иначе, он ответит кодом 23. После 3 отказов подряд майнер
  останавливается, чтобы не засыпать пул неверными шарами.

## Готовый Miner.exe (без Python, CUDA Toolkit и Rust)

Для тех, кто просто хочет майнить: собранный пакет `PearlMiner.zip` (~150 МБ; в репозиторий не кладётся из-за лимита
GitHub 100 МБ на файл — выкладывается в раздел Releases).

1. Распаковать в папку (лучше без кириллицы в пути).
2. Открыть `start_miner.bat` в Блокноте, вписать свой `WALLET` (`username/воркер` Kryptex или адрес PRL/воркер) и при
   необходимости `POOL`.
3. Запустить `start_miner.bat`. Проверка без пула: `Miner.exe --selftest`.

Нужны только Windows x64, видеокарта NVIDIA RTX 30xx или новее и актуальный драйвер (CUDA 13). Проверено на RTX 3060 Ti;
другие карты не тестировались (архитектура определяется автоматически, но ядро подбиралось под sm_86).

Сборка из исходников (нужен этот проект с `.venv`, см. «Установка» выше):

```powershell
.\.venv\Scripts\python -m pip install pyinstaller
.\.venv\Scripts\python build_exe.py
```

Результат: `release\PearlMiner\` и `release\PearlMiner.zip`. `build_exe.py` собирает PyInstaller-пакет (режим onedir),
кладёт рядом только нужные библиотеки CUDA (NVRTC, cudart, nvJitLink, заголовки; без cuBLAS/cuFFT/…, экономия > 1 ГБ),
добавляет шаблон `dist_files/start_miner.bat` (без чьих-либо личных данных) и `dist_files/README.txt`.
Собранный exe проверялся в чистом окружении без Python в PATH: `--selftest` и майнинг в локальный фейковый пул
(79 принятых шаров, 0 отказов). Антивирусы нередко ругаются на любые майнеры и неподписанные exe — это ожидаемо.

## Ограничения и что не сделано

* **Реальный gateway/узел не проверялись.** Клиент проверен на локальном фейковом сервере с официальными схемами.
* **Stratum для Kryptex не проверен на реальном пуле** (см. раздел выше). Протокол не выдумывался: используется только публичная спецификация.
* Только dense-режим; **MoE не поддерживается** (ядро и пайплайн рассчитаны на обычную матрицу A×B).
* Быстрое ядро — только тайл 4×16 при `m`, `n` кратных 128; остальные паттерны идут на простое (медленное, но корректное) ядро.
* Случайные A/B на GPU генерирует счётчиковый splitmix64 (значения −64…64), а не `rand` из Rust — это допустимо для майнинга,
  но побитово с эталоном они не сравниваются (проверяются диапазон и равномерность).
* Одна попытка за раз на одной карте; нет потоков CUDA для перекрытия попыток, нет мультикарт.
* Энергопотребление, температуры и стабильность при длительной работе не измерялись. Разгон и настройки драйвера не менялись.
* ZK-доказательство (plonky2) строит gateway; майнер отдаёт только `PlainProof`.
